## 工作流与权限

- 真正从 4 张参考图开始，主图优先/其他图按位置传入；素材内容来自本地媒体库。
- Mock 识图输出等待人工确认；直接 API 绕过、删除或降级高风险字段均拒绝。未确认商品不能策划；未确认方案不能生图；无效数量、缺变体和结构错误拒绝。
- 5/10/15 张方向与索引通过测试，详情图固定模块保持；主展示固定 5 张。
- 8 个相同幂等请求并发只建 1 个批次、5 个任务；同键不同场景返回 409。8 个执行者并发只产生一次有效领取、一次图片/用量。
- 批次冻结方案设置；后来编辑策划不会改变既有批次尺寸。重新识图后旧策划在 API 和工作台中失效。这是新增的最小关联，不是完整依赖哈希链。
- 另一账号无商品/历史，不能读取其他用户的批次、事件或成图，也不能重试。浏览器退出后未残留上一身份商品内容。

## 固定部分失败与恢复

真实 Redis/Dramatiq 独立进程执行：第 3 张首次在 Mock Provider 边界失败，状态为 partial，4 张已落库、1 张失败。手动重试只重排失败项，完成后尝试次数 `[1,1,2,1,1]`，4 个原图片 ID 不变；实际尝试用量为 6。重复相同重试幂等键不会再次执行。

浏览器同样验证了该场景、终态刷新恢复、单项重试、正常第二商品、跨商品切换、选中结果 ZIP 下载和 390px 手机布局。截图已查看，页面无横向溢出。Mock 标识和成功/失败数始终可见；100% 表示本轮任务都已到终态，不能当作全成功。

SSE 在真实数据库终态事件上验证 Last-Event-ID 续读，前端保留原生重连及数据库轮询；不承诺任意历史清理场景下的严格无重复投递。

## 真实进程与 PostgreSQL

进程夹具只接受本候选测试端口 25437，且只控制自己创建的子进程。

1. **SIGKILL**：第一代已领取且 Provider 返回后进程被强制结束；真实租约过期后新进程以 attempts=2 完成。
2. **SIGSTOP/SIGCONT，旧成功结果**：第一代取得结果后暂停，第二代接管保存；恢复第一代后 owned_write=false，只有一条图片记录，新图片 ID 不变。
3. **SIGSTOP/SIGCONT，旧错误**：旧执行恢复后抛错，同样不能覆盖第二代完成状态或图片。
4. **心跳**：正常 Provider 执行跨过初始 TTL，仍不能接管；已经过期的租约不能被迟到心跳复活。
5. **取消/额度**：执行中取消拒绝迟到结果；两并发执行者在额度为 1 时只产生一次实际用量与一张图片。

轨迹位于 `runtime/test-evidence/process-kill.json`、`process-late_success.json`、`process-late_error.json`、`dramatiq-partial-retry.json`。原始 JUnit、浏览器报告和截图由本地整理目录保存，运行产物不进入候选 Git。
